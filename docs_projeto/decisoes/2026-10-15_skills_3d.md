# 2026-10-15 — Skills de modelagem 3D

## Pedido

Adicionar como skill ou plugin, para modelagem 3D: `anatomy`, `three-agent-skills`,
`claude-skill-registry`, `Atlas-Agent-Teams`, `dominations`, `code-buddy`, `cad-agent`.

## Respostas do usuario

- Escopo: CAD parametrico, 3D na web, assets Blender e ilustracao tecnica
- Formato: fork em `.claude/skills/` (nao plugin)
- Execucao: **so texto** — nenhum script, servidor ou container entra
- Aceite: precedencia sem colisao + docs e fichas
- Entrega: fork do texto + skill CAD propria
- Bordas: aceitar skill inerte em projeto sem 3D; `anatomy` so para figura de documentacao

## O que mudou

1. Fork de texto de `emalorenzo/three-agent-skills@f950f95`: `three-best-practices` e
   `r3f-best-practices` (`SKILL.md` + `rules/`, sem os `.zip`)
2. Fork de texto de `TerminalSkills/skills@6edcf94` (origem real, nao a copia do
   `dominations`): `blender-scripting`, `-render-automation`, `-animation`, `-compositing`,
   com `LICENSE.txt` (Apache-2.0)
3. Bloco "Guardas deste fork" abaixo do frontmatter das seis. `blender-scripting` ganhou
   exclusao na `description` (peca de fabricacao vai para CAD)
4. Skill propria `cad-parametrico`: build123d padrao, OpenSCAD/CadQuery quando o projeto ja
   usa; perguntas obrigatorias; uma funcao por feature; verificacao por codigo sem afirmar
   validade sem rodar. `references/fabricacao.md` (folgas, furos, insertos) e
   `references/build123d.md` (idiomas que o agente erra)
5. `skills-lock.json`: seis entradas com `sourceCommit`, `upstreamSha256`, `license`,
   `forkChanges`. Campo `computedHash` nao usado: o algoritmo do CLI `skills` nao e sha256
   do `SKILL.md`, e inventar valor ali seria registro falso
6. [[../SKILLS|SKILLS.md]] secao 9 (precedencia 3D); contagem 50 → 57
7. Oito fichas `referencias/skill3d-*.md`

## O que ficou de fora e por que

| Referencia | Motivo |
|---|---|
| `anatomy` | O produto e o `kit/` Node + Chrome; `publish.mjs` usa rede. Contradiz "so texto". Description disputa gatilho com as esteticas |
| `cad-agent` | Executa Python recebido por HTTP sem autenticacao em `0.0.0.0`; Docker; licenca PolyForm. Ficou so a ideia do loop modelar-medir |
| `Atlas-Agent-Teams` | Duplica `.claude/agents/` e `/issue`; `.mcp.json` com pacotes `@anthropic/mcp-*` provavelmente nao oficiais |
| `claude-skill-registry` | Indice, nao skill; o proprio README diz que listagem nao prova autoria nem seguranca |
| `code-buddy` | Outro agente, sem 3D, BUSL-1.1 |
| `dominations` | Jogo 2D; skills Blender sem licenca propria e defasadas — buscadas na origem |

## Alternativas descartadas

- **Plugin via marketplace**: atualiza do upstream sem revisao e fica no nivel do usuario,
  fora do template. Contradiz a politica de fork de [[../SKILLS|SKILLS.md]] secao 6
- **cad-agent em Docker preso em 127.0.0.1**: resolveria a exposicao, nao a licenca nem a
  execucao de codigo arbitrario; e o usuario escolheu "so texto"

## Riscos aceitos

- `three-best-practices` envelhece com o Three.js (assume 0.182+). Guarda manda conferir o
  `package.json`
- `three-agent-skills` declara MIT so no `package.json`, sem arquivo `LICENSE`
- Numeros de `fabricacao.md` sao pontos de partida, nao norma; a skill diz isso
- Nenhuma skill 3D foi testada numa tarefa real ainda. Primeiro uso em projeto derivado
  deve virar ajuste aqui
